3. DATA FLOW BETWEEN TRAINER AND CLIENT
================================================================================

FIRESTORE COLLECTIONS STRUCTURE:
--------------------------------

A. Primary System: trainer_clients Subcollection
   Path: trainer_clients/{trainerUid}/clients/{clientUid}
   
   Data Structure:
   {
     id: clientUid,
     name: "Client Name",
     email: "client@email.com",
     photoURL: "https://...",
     height: 70, // inches
     weight: 180, // lbs
     age: 30,
     gender: "male",
     goals: "lose_fat",
     fitnessLevel: "intermediate",
     equipmentAccess: ["dumbbells", "barbell"],
     daysPerWeek: 4,
     injuries: null,
     phone: "+1234567890",
     bio: "Client bio",
     role: "client",
     status: "active", // active | pending | inactive
     joinedAt: timestamp,
     createdAt: timestamp,
     updatedAt: timestamp,
     lastActivity: timestamp
   }

   Subcollections:
   - trainer_clients/{trainerUid}/clients/{clientUid}/workouts/{workoutId}
   - trainer_clients/{trainerUid}/clients/{clientUid}/progress/{progressId}
   - trainer_clients/{trainerUid}/clients/{clientUid}/messages/{messageId}

B. Users Collection
   Path: users/{userId}
   
   Client Document:
   {
     uid: userId,
     email: "client@email.com",
     name: "Client Name",
     role: "client",
     trainerId: trainerUid, // Set when trainer adds client
     trainerAssignedAt: timestamp,
     // ... other user profile data
   }
   
   Trainer Document:
   {
     uid: userId,
     email: "trainer@email.com",
     name: "Trainer Name",
     role: "trainer",
     bio: "Trainer bio",
     credentials: "NASM-CPT",
     specializations: ["Strength Training", "HIIT"],
     location: "New York, NY",
     photoURL: "https://...",
     rating: 4.9,
     reviewCount: 50
   }

C. Messages Collection
   Path: messages/{combinedUid}/messages/{messageId}
   Format: combinedUid = "{trainerUid}_{clientUid}" (sorted alphabetically)
   
   Message Document:
   {
     senderUid: userId,
     receiverUid: userId,
     text: "Message content",
     timestamp: timestamp,
     read: false,
     readAt: null
   }

D. Conversations Collection
   Path: conversations/{conversationId}
   
   Conversation Document:
   {
     participants: [trainerUid, clientUid],
     lastMessage: "Last message text",
     lastMessageAt: timestamp,
     unreadCount: { [userId]: count },
     createdAt: timestamp
   }

E. Workouts Collection (Legacy/Alternative)
   Path: workouts/{trainerUid}/clients/{clientUid}/workouts/{workoutId}
   
   Workout Document:
   {
     name: "Workout Name",
     exercises: [...],
     date: timestamp,
     duration: 45, // minutes
     completed: false,
     completedAt: null,
     createdAt: timestamp
   }

DATA FLOW PATTERNS:
-------------------

1. TRAINER ADDS CLIENT:
   Flow: TrainerMarketplaceModal → clientCRMService.createOrUpdateClient()
   
   Steps:
   a. Trainer accepts client request from marketplace
   b. Validate roles (trainer role, client role)
   c. Check for existing relationship
   d. Create document in trainer_clients/{trainerUid}/clients/{clientUid}
   e. Sync all client data from users/{clientUid} to CRM
   f. Auto-create conversation in conversations collection
   g. Update users/{clientUid} with trainerId field
   h. Initialize welcome message in messages collection
   
   Result:
   - Client appears in trainer's dashboard
   - Conversation automatically created
   - Client can see trainer in their app
   - Real-time updates via Firestore listeners

2. TRAINER VIEWS CLIENT DATA:
   Flow: PremiumTrainerDashboard → Firestore queries
   
   Steps:
   a. Fetch client list from trainer_clients/{trainerUid}/clients
   b. For each client, fetch updated info from users/{clientUid}
   c. Merge data (users collection is source of truth)
   d. Display in dashboard with real-time updates
   
   Data Sources:
   - Client profile: trainer_clients + users (merged)
   - Workouts: trainer_clients/{trainerUid}/clients/{clientUid}/workouts
   - Progress: trainer_clients/{trainerUid}/clients/{clientUid}/progress
   - Nutrition: users/{clientUid}/nutrition_logs (or separate collection)
   - Messages: messages/{combinedUid}/messages

3. CLIENT VIEWS THEIR DATA:
   Flow: PremiumHomeScreen → Multiple data sources
   
   Steps:
   a. Fetch user data from users/{clientUid}
   b. Fetch today's workouts from workoutService
   c. Fetch nutrition logs for today
   d. Calculate stats (calories, streak, etc.)
   e. Fetch trainer info if trainerId exists
   f. Subscribe to real-time updates
   
   Data Sources:
   - Profile: users/{clientUid}
   - Workouts: workoutService (queries user's workouts)
   - Nutrition: nutritionService (queries user's food logs)
   - Trainer: users/{trainerId} (if assigned)
   - Messages: conversations collection

4. TRAINER ASSIGNS WORKOUT TO CLIENT:
   Flow: Trainer → WorkoutLibraryScreen → Firestore write
   
   Steps:
   a. Trainer creates/selects workout
   b. Assign to client via:
      trainer_clients/{trainerUid}/clients/{clientUid}/workouts/{workoutId}
   c. Client's home screen updates via real-time listener
   d. Workout appears in client's "Today's Workout" hero card
   
   Data Path:
   - Write: trainer_clients/{trainerUid}/clients/{clientUid}/workouts
   - Read: Client queries same path or workoutService filters by userId

5. CLIENT COMPLETES WORKOUT:
   Flow: Client → ActiveWorkoutScreen → Firestore update
   
   Steps:
   a. Client starts workout from home screen
   b. Logs exercises, sets, reps
   c. Marks workout as completed
   d. Updates workout document with:
      * completed: true
      * completedAt: timestamp
      * exerciseData: [...]
   e. Trainer sees completion in real-time
   f. Updates client's lastActivity timestamp
   
   Data Path:
   - Update: trainer_clients/{trainerUid}/clients/{clientUid}/workouts/{workoutId}
   - Also: May write to user's workout history collection

6. MESSAGING FLOW:
   Flow: Trainer/Client → MessagesView → Firestore messages
   
   Steps:
   a. Get or create conversation via getOrCreateConversation()
   b. Send message to messages/{combinedUid}/messages
   c. Update conversation document with lastMessage
   d. Update unreadCount for receiver
   e. Real-time listener updates UI for both parties
   
   Data Path:
   - Messages: messages/{combinedUid}/messages/{messageId}
   - Conversation: conversations/{conversationId}
   - Unread counts: conversations/{conversationId}.unreadCount

7. PROGRESS TRACKING FLOW:
   Flow: Trainer → ProgressView → Firestore progress
   
   Steps:
   a. Trainer views client's progress tab
   b. Fetches from: trainer_clients/{trainerUid}/clients/{clientUid}/progress
   c. Displays weight trends, measurements, photos
   d. Client can also log progress (if permissions allow)
   
   Data Path:
   - Progress entries: trainer_clients/{trainerUid}/clients/{clientUid}/progress/{progressId}
   - Analytics calculated from progress history

REAL-TIME UPDATES:
------------------
- Trainer dashboard uses onSnapshot for client list
- Client home screen uses onSnapshot for workouts
- Messages use onSnapshot for real-time chat
- Unread counts update in real-time
- Workout completions sync immediately
- Progress updates reflect instantly

DATA SYNCHRONIZATION:
---------------------
- users/{clientId} is source of truth for client profile
- trainer_clients/{trainerUid}/clients/{clientUid} syncs from users collection
- syncClientDataFromUsers() function ensures CRM stays updated
- When client updates profile, trainer's CRM can be synced
- Two-way sync for messages (both can read/write)
- One-way sync for workouts (trainer assigns, client completes)

SECURITY & PERMISSIONS:
----------------------
Firestore Rules:
- trainer_clients: Trainer can create/read/update/delete their clients
- Client can read their own data in trainer_clients
- Messages: Only participants can read/write
- Workouts: Trainer can create/update, both can read
- Progress: Trainer can create/update, both can read

A. FIRESTORE PERMISSION ERRORS (CRITICAL)
================================================================================

1. "Missing or insufficient permissions" / "FirebaseError: Missing or insufficient permissions"
   Error Code: permission-denied
   
   WHERE IT HAPPENS:
   - Nutrition page when loading food logs
   - When trying to save nutrition goals
   - When trainer tries to add client to CRM
   - When trying to read/write to trainer_clients collection
   - When accessing any collection without proper rules
   
   COLLECTIONS AFFECTED:
   - nutrition_logs - Food logs (user's food entries)
   - nutrition_goals - Nutrition goals (user's calorie/macro targets)
   - trainer_clients/{trainerUid}/clients/{clientUid} - CRM system
   - clients - Legacy CRM collection
   - app_errors - Error logging collection
   - Any collection missing from firestore.rules
   
   ROOT CAUSE:
   Firestore security rules don't allow the operation
   
   FIX:
   1. Go to https://console.firebase.google.com/
   2. Select project: coachconnect-auth
   3. Go to Firestore Database → Rules tab
   4. Copy rules from firestore.rules file
   5. Paste and click "Publish"
   6. Wait 30 seconds for rules to propagate
   
   FILES TO CHECK:
   - firestore.rules - Main rules file
   - src/nutrition/services/nutritionService.js - Has error handling
   - src/trainer/services/clientCRMService.js - CRM operations
   
   STATUS: 🔴 CRITICAL - Blocks core features

2. "Failed to load food logs: [FirebaseError: Missing or insufficient permissions.]"
   WHERE: Nutrition screen, MealPlanHomeScreen
   FIX: Add nutrition_logs rules (already in firestore.rules lines 118-133)
   
3. "Failed to load goals, using default: Missing or insufficient permissions."

K. COMPLETE ERROR CODE REFERENCE
================================================================================

FIRESTORE ERROR CODES:
- permission-denied: Security rules blocked the operation
- not-found: Document/collection doesn't exist
- already-exists: Document already exists (on create)
- failed-precondition: Index required or invalid query
- aborted: Operation was aborted
- out-of-range: Invalid argument value
- unimplemented: Operation not supported
- internal: Internal Firebase error
- unavailable: Service unavailable (network issue)
- deadline-exceeded: Operation timed out
- unauthenticated: User not authenticated
- resource-exhausted: Quota exceeded

AUTH ERROR CODES:
- auth/user-not-found: No user with that email
- auth/wrong-password: Incorrect password
- auth/invalid-email: Invalid email format
- auth/user-disabled: Account disabled
- auth/too-many-requests: Rate limited
- auth/email-already-in-use: Email already registered
- auth/weak-password: Password too weak
- auth/account-exists-with-different-credential: Account exists with different provider
- auth/popup-blocked: Browser blocked popup
- auth/popup-closed-by-user: User closed popup
- auth/operation-not-allowed: Provider not enabled

M. ERROR PREVENTION BEST PRACTICES
================================================================================

1. ALWAYS check if db/auth/storage is initialized before use:
   if (!db) return;
   if (!auth) return;
   if (!storage) return;

2. ALWAYS wrap Firestore operations in try-catch:
   try {
     const doc = await getDoc(docRef);
   } catch (error) {
     console.error('Error:', error);
     // Handle error
   }

3. ALWAYS check authentication before Firestore operations:
   if (!auth.currentUser) {
     // Redirect to login
     return;
   }

4. ALWAYS validate data before writing:
   if (!userId || !data) {
     throw new Error('Missing required parameters');
   }

5. ALWAYS handle permission-denied errors gracefully:
   if (error.code === 'permission-denied') {
     // Show user-friendly message
     // Log error for debugging
   }

6. ALWAYS check if document exists before reading:
   if (!doc.exists()) {
     // Handle missing document
     return null;
   }

7. ALWAYS use serverTimestamp() for timestamps:
   createdAt: serverTimestamp()

8. ALWAYS validate Firestore rules match your queries:
   - Check collection names match
   - Check field names match (userId vs user_id)
   - Check authentication requirements
